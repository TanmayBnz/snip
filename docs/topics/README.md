# snip topic notes

Study/reference notes on every technology `snip` uses, written to be defensible out
loud in an interview — not tutorials. One file per topic, four sections each: what it
is, how it's used here (real paths/config/numbers), what someone would ask, what's not
done.

Written incrementally, right after each piece is actually built — a note written
before the code exists would be guessing, not grounding.
